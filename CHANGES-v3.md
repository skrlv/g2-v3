# v3 — скорость, аналитика, доставка, письма (сентябрь 2026)

Поверх v2 (`CHANGES-v2.md`). Проверено: `npm run typecheck`, `npm run lint`,
`npm run build`; сквозной заказ через API с регионом и телефоном; загрузка фото в
папку и раздача; письмо через SMTP-заглушку; прогон страниц на 1440 и 390px.

База обновляется сама при первом запросе: в `orders` добавляются `shipping_zone`
и `shipping_cents`. Новые зависимости: `@aws-sdk/client-s3`, `nodemailer` — нужен
`npm install`.

## Скорость

- **next/image для всех фото каталога** (`components/picture.tsx`): карточки, галерея,
  герой, блоки «фото + текст», миниатюры в корзине. Браузер получает AVIF/WebP нужной
  ширины: обложка карточки в сетке — ~18 КБ вместо 234 КБ JPEG. Подсказки `sizes`
  собраны в `SIZES`. Фото из базы (data-URL) и с чужих хостов отдаются как есть.
- **Хранилище фото из студии** (`lib/storage.ts`, `api/upload`): S3-совместимое по
  `S3_*`, иначе папка `UPLOADS_DIR` с раздачей через `/uploads/<имя>`, иначе — база,
  как раньше. На сервере фото приводится к WebP ≤1600 px (`sharp`), имя — хэш содержимого,
  кэш бессрочный. В студии под фото показывается, какой режим настроен.
  `POST /api/admin/migrate-images` переносит старые data-URL из базы в хранилище.
  Dockerfile задаёт `UPLOADS_DIR=/app/uploads` и объявляет том.
- **Зерно выключено на телефонах** (ниже 640px): слой с `mix-blend-mode` поверх всей
  страницы заметно грузил GPU на Android при нулевой пользе на 6-дюймовом экране.

## Аналитика

- **Яндекс.Метрика** (`components/analytics.tsx`, `lib/analytics.ts`) по
  `NEXT_PUBLIC_YM_ID`; без переменной на странице нет ни строчки счётчика. Переходы
  внутри сайта отправляются как `hit`. Вебвизор выключен (`NEXT_PUBLIC_YM_WEBVISOR=true`
  включает — только если это отражено в политике конфиденциальности).
- Цели: `add_to_cart` (с ценой), `order` (с номером и суммой), `subscribe`, `contact`.
  Электронная коммерция через `dataLayer`: `add` и `purchase` с составом заказа —
  в Метрике появится отчёт «Заказы» с доходом по товарам.
- `NEXT_PUBLIC_*` подставляются при сборке — задайте переменную до `next build`.

## Доставка и заказ

- **Единая таблица зон** `lib/shipping.ts`: её читают страница «Доставка», корзина,
  заказ, письмо и Telegram. Для Москвы и МО тариф ниже порога в исходной таблице не был
  указан — стоит `null`, покупатель видит «по тарифу курьера — уточним при
  подтверждении», в сумму заказа это не входит. Впишите число в `SHIPPING_ZONES` —
  всё остальное подхватится само.
- **Корзина**: выбор региона (запоминается на устройстве), срок, стоимость доставки,
  линейка до бесплатной доставки для зон с порогом, «Итого» с доставкой. Для зарубежья —
  напоминание про пошлины.
- **Заказ** хранит зону и стоимость доставки; студия показывает их в списке заказов и
  считает итог с доставкой.
- **Телефон**: маска `+7 (999) 123-45-67` при вводе (иностранные номера — свободно),
  на сервере номер нормализуется в `+7XXXXXXXXXX`; неполный номер отклоняется с понятным
  текстом.

## Письмо покупателю

- После заказа уходит письмо с номером, составом, доставкой и тем, что будет дальше
  (`lib/mail.ts`, `nodemailer`, любой SMTP по `SMTP_*` и `MAIL_FROM`). Без настроек
  письма не отправляются, заказ работает как раньше. На экране «Заказ принят» видно,
  ушло ли подтверждение.
