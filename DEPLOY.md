# G2 — публикация сайта и управление контентом

Сайт — это Next.js (App Router) + PostgreSQL (через Drizzle ORM).
База нужна всегда: в ней товары, заказы, сообщения, подписчики и фото,
загруженные в студии.

---

## 1. Переменные окружения

| Переменная | Обязательна | Что это |
| --- | --- | --- |
| `DATABASE_URL` | да | строка подключения к PostgreSQL, например `postgresql://user:pass@host:5432/g2?sslmode=require` |
| `ADMIN_PASSWORD` | **да, на проде** | пароль для входа в `/admin` и для изменения каталога. Логин — любой. Без пароля студия на проде отвечает «выключена», а не открывается всем. Кириллица в пароле допустима. |
| `NEXT_PUBLIC_SITE_URL` | желательно | адрес сайта для превью в соцсетях, например `https://g2wear.ru` (на Vercel без неё берётся адрес деплоя) |
| `TELEGRAM_BOT_TOKEN` | нет | токен бота от @BotFather — тогда каждый заказ и сообщение из «Контактов» приходят вам в Telegram |
| `TELEGRAM_CHAT_ID` | нет | ваш числовой id: напишите боту любое сообщение и откройте `https://api.telegram.org/bot<токен>/getUpdates`, поле `chat.id` |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PUBLIC_URL` | для Vercel — да | хранилище фото из студии, см. раздел «Фото» ниже |
| `UPLOADS_DIR` | нет | папка для фото на своём сервере (в Docker уже задана `/app/uploads`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | нет | письмо покупателю с подтверждением заказа; без них письма не уходят, всё остальное работает |
| `NEXT_PUBLIC_YM_ID` | нет | номер счётчика Яндекс.Метрики; цели `add_to_cart`, `order`, `subscribe`, `contact` и электронная коммерция через `dataLayer` |

Таблицы создаются автоматически при первом открытии сайта, каталог один раз
засевается из `src/db/seed-data.ts`. Вручную миграции гонять не нужно: мелкие
изменения схемы (новые поля) применяются при старте сами.

## 1a. Фото из студии — где хранятся

Фото, загруженные в `/admin`, приводятся к WebP до 1600 px и попадают:

1. **В S3-совместимое хранилище**, если заданы `S3_*` — Yandex Object Storage, Selectel,
   VK Cloud, Cloudflare R2, MinIO. Это единственный рабочий вариант на Vercel и другом
   serverless-хостинге: там диск не сохраняется между запусками. Бакет должен отдавать
   файлы публично; `S3_PUBLIC_URL` — его адрес без завершающего слэша
   (например `https://storage.yandexcloud.net/g2`). Если провайдер требует virtual-host
   адресацию, задайте `S3_PATH_STYLE=false`; если не принимает ACL — `S3_ACL=none`.
2. **В папку на диске** (`UPLOADS_DIR`), если S3 не задан — для Docker и VPS. В образе
   уже задано `/app/uploads`; примонтируйте том: `docker run -v g2-uploads:/app/uploads …`.
   Файлы раздаются по адресу `/uploads/<имя>`.
3. **В базу как data-URL**, если не задано ничего. Работает, но база и ответы API растут,
   а картинки не оптимизируются.

Перенести старые фото из базы в хранилище (после настройки S3 или `UPLOADS_DIR`):

```bash
curl -X POST -u admin:ВАШ_ПАРОЛЬ https://ваш-сайт/api/admin/migrate-images
```

Повторный вызов безопасен — переносятся только оставшиеся data-URL.

## 1b. Письмо покупателю и аналитика

- Письмо с номером заказа, составом и доставкой уходит покупателю, если заданы `SMTP_*`
  и `MAIL_FROM`. Для Яндекс 360: `SMTP_HOST=smtp.yandex.ru`, порт 465, пароль приложения.
- Яндекс.Метрика подключается по `NEXT_PUBLIC_YM_ID` (переменная подставляется при сборке — задайте её до `next build`). В настройках счётчика включите
  «Электронная коммерция» (контейнер `dataLayer`) и заведите цели типа «JavaScript-событие»
  с идентификаторами `add_to_cart`, `order`, `subscribe`, `contact`.

## 2. Вариант A — Vercel + Neon (рекомендуется, бесплатно)

1. **Код в GitHub.** Создайте репозиторий на github.com и загрузите проект:
   ```bash
   git init
   git add .
   git commit -m "G2 store"
   git branch -M main
   git remote add origin https://github.com/ВАШ_АККАУНТ/g2.git
   git push -u origin main
   ```
2. **База.** Откройте [neon.tech](https://neon.tech) → New project → скопируйте
   **Connection string** (это и есть `DATABASE_URL`).
   Альтернатива — [supabase.com](https://supabase.com) (Project Settings → Database → Connection string).
3. **Хостинг.** На [vercel.com](https://vercel.com) → Add New → Project →
   выберите репозиторий → Settings → Environment Variables:
   - `DATABASE_URL` = строка из Neon
   - `ADMIN_PASSWORD` = придумайте длинный пароль
   - `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — если хотите уведомления
   → Deploy.
4. Готово. Vercel выдаст адрес вида `g2.vercel.app`, там же можно привязать домен
   (Project → Settings → Domains). После привязки задайте `NEXT_PUBLIC_SITE_URL`.
5. **Обновления** — любой `git push` автоматически передеплоивает сайт.

---

## 3. Вариант B — Railway (всё в одном)

1. Залейте код в GitHub (шаг 1 выше).
2. [railway.app](https://railway.app) → New Project → Deploy from GitHub repo.
3. Add a service → **PostgreSQL**.
4. У приложения → Variables → добавьте:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `ADMIN_PASSWORD` = ваш пароль
5. Settings → Networking → Generate Domain.

Похожим образом работает [Render](https://render.com) (Web Service + PostgreSQL).

## 4. Вариант В — свой сервер (VPS) через Docker

Нужен Docker и доступный PostgreSQL (можно в том же Docker). База при сборке
образа не нужна — только при запуске.

```bash
docker build -t g2 .
docker run -d --name g2 -p 3000:3000 \
  -e DATABASE_URL="postgresql://postgres:postgres@ХОСТ:5432/g2" \
  -e ADMIN_PASSWORD="ПАРОЛЬ" \
  --restart unless-stopped g2
```

Nginx/Caddy перед контейнером — для HTTPS и домена. Сборка использует
`output: standalone` (см. `Dockerfile`). Во время сборки нужен доступ в интернет:
шрифты Google скачиваются в образ.

Локально без Docker:
```bash
npm install
DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5432/app_db" npm run dev
```

## 5. Заказы, сообщения, подписчики

Покупатель в корзине оставляет email, телефон, имя и адрес или комментарий.
Заказ сохраняется в базе со статусом «Новый», покупатель видит номер и сумму,
а вы получаете сообщение в Telegram (если настроен). Онлайн-оплаты пока нет:
вы связываетесь с покупателем и присылаете способ оплаты — так и написано на
сайте.

Все заказы, сообщения из «Контактов» и подписчики рассылки видны в студии:
`/admin` → вкладки «Заказы», «Сообщения», «Подписки» (кнопка «Обновить» подтянет
новые). Заказы в базе хранят копию позиций с ценами на момент заказа.

## 6. Как менять контент

### Карточки товаров, цены, фото, категории — через студию `/admin`

Откройте `/admin` напрямую (ссылки с сайта на студию нет). Менять можно прямо на
живом сайте, **без пересборки и программиста**:

- название, артикул, категория, цена в рублях;
- короткое описание и большой редакционный текст;
- **фото** — кнопка «+ Добавить фото», можно выбрать сразу несколько;
  файлы сжимаются в браузере до 1600 px и сохраняются в базе, обложка — первое
  фото (любую карточку можно назначить обложкой, навести на превью). Не больше
  12 фото на товар;
- размеры (через запятую), характеристики (строки вида `Ткань: хлопок 480 г/м²`);
- путь к 3D-модели `…/models/файл.glb` — оставьте пустым, и 3D-блока у товара
  просто не будет;
- галочки «На главной» и «Опубликован» (черновики не видны покупателям и не
  заказываются), позиция в каталоге;
- кнопка «+ Новый товар» и удаление (с подтверждением — фото пропадут вместе
  с товаром). Адрес (slug) нового товара должен быть свободен: существующий
  товар не перезаписывается.

### Тексты сайта, меню, контакты — в одном файле

Файл **`src/db/seed-data.ts`** (в начале файла — понятный комментарий):

- `siteCopy` — слоган, подзаголовок героя, координаты, email, ссылки на соцсети;
- `siteNav` — пункты меню (Главная / Каталог / О бренде / Доставка / Контакты);
- `seedProducts` — стартовый каталог: имена, цены, описания, пути к фото и т.д.

Как поменять на проде без локальной установки:

1. Откройте файл на GitHub → карандаш ✏️ (Edit) → поменяйте текст → Commit changes.
2. Vercel/Railway сами передеплоят (1–2 минуты).
3. Чтобы новые товары из `seedProducts` попали в базу, откройте `/admin` и нажмите
   **«Добавить из файла контента»** — добавятся только те, которых ещё нет;
   товары, уже отредактированные в студии, не изменятся. Перезаписать всё из
   файла можно запросом `POST /api/seed?overwrite=true` (с паролем студии).

Тексты на отдельных страницах (О бренде, Доставка, Контакты, Условия,
Конфиденциальность) — это файлы в `src/app/<страница>/page.tsx`, правятся так же,
через коммит на GitHub.

### Фото и 3D как файлы (альтернатива загрузке в студии)

- Положите картинки в `public/images/...` (на GitHub — Add file → Upload files),
  затем укажите путь, например `/images/products/hoodie.jpg`, в товаре —
  в студии есть «Расширенный режим: пути к файлам».
- 3D-модели — в `public/models/*.glb` или `*.gltf`, путь в поле модели.

### Логотип

Сейчас логотип — текстовый знак **G2** дисплейным шрифтом (`Logo` в
`src/components/brand.tsx`, стили — `.logo-mark` в `src/app/globals.css`).
Менять начертание/наклон можно стилями; буквы — компонентом `Logo`.

## 7. Защита

- Студия, загрузка фото, синхронизация из файла, изменения товаров и список с
  черновиками закрыты паролем; запросы с чужих сайтов отклоняются.
- Формы заказа, контактов и подписки ограничены по числу запросов с одного
  адреса и по длине полей; в формах есть скрытое поле-ловушка для ботов.
- Ошибки сервера не показываются покупателю в подробностях — смотрите логи
  хостинга.

## 8. Бэкапы и обслуживание

Фото из студии лежат в базе (data-URL) — бэкапьте базу целиком:

```bash
pg_dump "$DATABASE_URL" -Fc -f g2-$(date +%F).dump
# восстановление
pg_restore --clean -d "$DATABASE_URL" g2-2026-01-01.dump
```

Рекомендуется настроить ежедневный дамп (Neon и Supabase делают снапшоты сами,
но у бесплатных планов окно восстановления короткое).

**Чеклист продакшена**

- [ ] задан `DATABASE_URL`, сайт открывается и каталог на месте;
- [ ] задан надёжный `ADMIN_PASSWORD`, `/admin` спрашивает пароль;
- [ ] задан `NEXT_PUBLIC_SITE_URL`, привязан домен и включён HTTPS;
- [ ] настроен Telegram — тестовый заказ пришёл в чат;
- [ ] настроены бэкапы базы;
- [ ] заказ с тестовой почты виден в `/admin` → «Заказы», сообщение из «Контактов» — в «Сообщениях».
